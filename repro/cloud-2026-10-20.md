## Gaps (numbered, most severe first)

### Found by running the commands

1. **On a fresh clone with Claude Code installed, `python autoloop.py <n>` launches a real
   agent with permission checks off.** `dispatch_proposer()` runs
   `claude -p <prompt> --model sonnet --permission-mode bypassPermissions`.
   - It runs in `Path("E:/demiurge-runs")/proposer_<ts>`. On POSIX that is a *relative*
     path, so it creates `./E:/demiurge-runs/…` under the caller's cwd and leaves
     `?? E:/` in `git status`.
   - Shown with a stub `claude` that only logged its argv (command 16). With the real CLI,
     a stranger would spend their own quota on an unattended agent. If that agent produced
     files, `proposals/auto_<ts>/` would also be written into the repo before the gate
     failed.
   - `hunt.py`, which the README never mentions, has the same dispatch.
   - The README's "run on the author's machine, not on a fresh clone" tells a stranger they
     simply won't work. It should instead warn them not to run these commands.

2. **`reproduce.py` fails about 1.4% of runs with no change to the repo.**
   - p001 is an exact DP solver. It ties the greedy baseline whenever greedy is also
     optimal: 18 of 6,200 random seeds = 0.29% (95% CI 0.18–0.46%).
   - The check requires a strict `>`, so a tie exits 1. That gives REJECTED, then
     `MISMATCH`, then `REPRODUCE: FAIL`.
   - Per run with the default 5 holdouts: P(FAIL) = 1.44% (0.92–2.27%). With
     `--holdout 2`: 0.58%.
   - Each CI push runs 4 jobs, so P(at least one red job) ≈ 5.6%.
   - Deterministic repro:
     `cd proposals/p001-dp-scheduler/bundle && PYTHONPATH=../../.. python3 check.py 8965032`
     prints `seed=8965032 organ=764 baseline=764` and exits 1.
   - The README's "Not claimed" section covers the opposite error (the overfit falsely
     certified, ≈0.004% at 5 holdouts) but not this one, which is about 400× more likely.
     It also means the live 2-seed gate would have rejected the genuine p001 about 0.6% of
     the time.

3. **`python driver.py cycle <proposal>` on a fresh clone records a false rejection.**
   - With `node` on PATH, the gate script `E:\atlas-station\scripts\claim-gate.mjs` doesn't
     exist. Node's error goes to stderr, and `gate()` captures stderr and drops it.
   - The driver then appends `attempt` + `rejected` lines for the genuine p001 to
     `ledger.jsonl`, with no reason field, and exits 2. The terminal shows only an empty
     line between the two `[ledger]` lines.
   - Without `node`, it leaves an orphan `attempt` line and then a traceback.
   - So the "HONEST LEDGER" rule in `driver.py` does not distinguish "gate unreachable"
     from "gate rejected". This code is in the sealed substrate.

4. **"in under ten seconds"** did not hold here: 11.6–14.3 s across 10 timed runs on a 4-vCPU
   2.8 GHz Xeon. It holds only on the two Linux CI runners (8.9 s, 9.7 s); Windows CI took
   11.5 s and 14.1 s. The HEAD commit message says "~7 s". A "typically 10–15 s" figure
   would be accurate. Cosmetic: the last line actually reads
   `REPRODUCE: PASS in 12.8 s`, and the README's sample omits the per-seed lines and the
   numbered step headers.

5. **DESIGN.md still carries the false accusation.** Line 13 of the sealed, "frozen"
   constitution lists "a fabricated citation" among Specimen 0's failures.
   CASE-RECORD.md Exhibit D and 24601.md retract that accusation, and CASE-RECORD says
   "Corrections have been issued to every downstream document". The README sends readers
   to the retraction, and DESIGN.md is the next document it links. Its own rule
   ("Amendments append") permits an appended correction, which would need a reseal.

6. **"all ledgered, all reproducible" / "Rejected → recorded, honestly, forever."**
   `ledger.jsonl` is gitignored and no ledger is published. The D2 cycle-2 event ("ran out
   of budget — and the machine halted honestly") has no artifact in the repo: no proposal
   directory and no ledger line. Its only evidence is the text of commit `7ad9eaa`. The
   gate verdicts reproduce; the halt and the ledger cannot be checked by a stranger.

7. **"The substrate seal was re-taken once."** The 2026-10-19 reseal is exactly as
   described. But `git log -- substrate.sha256` shows 5 commits. The sealed content of
   `driver.py` changed twice (`7ad9eaa`, `8dd7055`) and `autoloop.py` once (`7ddfcbf`),
   in operator reseals during development. "Once" reads as "the seal has changed once".
   Something like "the only reseal without a content change" would be accurate.

8. **"checks each verdict against git history."** `reproduce.py` never reads git. It
   compares results to a hard-coded `EXPECTED` dict whose comments cite commits. I checked
   those four commits by hand and they match, but a tarball download with no `.git` gets
   the same PASS. "against the verdicts recorded in git history (hard-coded, with commit
   refs)" would be precise.

9. **`python` is not a command on stock Ubuntu 24.04** unless `python-is-python3` is
   installed. It worked here only because this VM image adds an alternatives link.
   `python3 reproduce.py` behaves identically, so a one-line note ("`python3` on
   Linux/macOS") would close this gap.

10. **Commit `5995575` says the overfit "loses to champion on unseen seed 1958237"; it
    ties** (2043 = 2043). In 200 random seeds it never lost (174 tie, 26 win). The README's
    "ties the champion" is the accurate phrasing; only the commit message is off.

11. **p002-memorizer was a planted control, not a caught gaming attempt.** Its own
    docstring says "gamed fixture … Exists to prove the gate kills this class of
    proposal." The README's D1 row ("A gamed proposal (memorized answers) … rejected")
    doesn't say the operators built it. A stranger could read it as gaming caught in the
    wild.

12. **The certificate covers only the inequality, not the claim's wording.**
    auto_20260702_233403's claim statement says it outscores the champion "by 280-600
    points across all tested seeds". On random seeds the margin ranged 140–734 (one of my
    `reproduce.py` holdouts: 235). p001's statement ("OUTSCORES the substrate baseline")
    is false on 0.29% of seeds. DESIGN.md's "What the gate cannot do" section gets close to
    this; the README doesn't say it.

### README language a passing stranger can't verify or may find off-putting

    proposer invented a multi-start local-search solver, verified its claim before making
    it."

      fixed prompt that tells it to verify before claiming. So "verified its claim" was an
      instruction it was given.
    - "Invented" overstates: multi-start 1-flip local search is a textbook heuristic.
    - What got "improved" in the shipped runs is a ~65-line max-cut solver file
      (`organ/m1_solver.py`). The proposer's model and prompt are untouched by the loop.
    - "Recursive self-improvement experiment" sets an expectation the README never scopes
      down.
